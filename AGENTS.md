# AGENTS.md

Guidance for contributors and coding agents working in this repository.

## What this is

`team-task-nexus` is a REST API for team task management in Go: teams with owner, admin and member
roles, tasks with partial updates and a per-field change history, comments, and team analytics.
Storage is MySQL through sqlx; Redis holds the task list cache and the rate limiter windows. Task
assignments and comments emit events through a transactional outbox, delivered to a webhook or to the
log. The HTTP layer is chi; metrics go to Prometheus, logs through `log/slog`.

## Layout

```text
cmd/api/              entry point: config, logger, signals, app.New and Run - keep it thin
api/                  OpenAPI 3.1 contract, embedded and served at GET /openapi.yaml
internal/app/         wiring, MySQL and Redis connections, migrations, HTTP server, workers, shutdown
internal/config/      environment configuration (cleanenv, optional .env) and its validation
internal/domain/      entities, enums with Valid(), domain events; no JSON or SQL tags
internal/port/        interfaces between layers: repositories, TxManager, cache, rate limiter,
                      outbox, event sender, token verifier, services, Pinger
internal/service/     business logic and the outbox dispatcher; depends only on domain, port, internal/pkg
internal/adapter/     http (router, handlers with DTOs, middleware, response envelope),
                      mysqlrepo (sqlx repositories, TxManager, outbox), redisstore (cache, rate limiter),
                      notify (webhook and log senders)
internal/pkg/         apperror, logger, metrics, opt (PATCH fields)
migrations/           SQL migrations, embedded and applied at startup
test/integration/     end-to-end tests against MySQL and Redis containers (testcontainers)
test/mocks/           gomock mocks of internal/port, generated by `make generate`
docs/adr/             architecture decision records
```

Dependency rule: `internal/service` imports only `internal/domain`, `internal/port` and
`internal/pkg` (its tests also `test/mocks`), never an adapter; `TestLayering` in
`internal/service/deps_test.go` enforces it.
Transactions cross layers via `port.TxManager` and `context.Context`: repositories join the
transaction found in the context and otherwise run on the pool, so anything that must be atomic is
wrapped in `WithinTx` by the service. `GetByIDForUpdate` and `OutboxRepository.Add` must run inside it.

Access rules (ADR 0002): a non-member gets 404 for a team and for everything in it, a member without
the needed role 403; every list query is scoped to the caller's teams in SQL. Keep both when adding
endpoints.

## Commands

```text
make help              list targets
make run               run the API locally (expects MySQL and Redis, see .env.example)
make up / make down    API, MySQL, Redis and Prometheus via docker compose; down removes the volumes
make test              unit tests with race detector and coverage (-short skips the integration suite)
make test-integration  integration tests (needs Docker)
make lint              golangci-lint v2 (config in .golangci.yml)
make fmt               gofmt and goimports through golangci-lint
make generate          regenerate the mocks after changing an interface in internal/port
make vuln              govulncheck
make build             static binary in bin/
```

CI runs `go mod tidy -diff`, a check that the generated mocks are up to date, golangci-lint, unit and
integration tests, gosec, govulncheck, the binary and image build and a Trivy scan. gosec (high
severity and confidence) and Trivy (fixable CRITICAL and HIGH findings) block the image publish;
govulncheck is advisory. Keep all of it green.

## Conventions

- Code, comments, identifiers and commit messages are in English. User documentation (README) is in
  Russian; ADRs are in English.
- Commit messages follow Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`,
  `build:`, `ci:`).
- Errors cross layers as `*apperror.AppError` with a string code; handlers answer them with
  `response.Error`, which turns anything else into a generic 500 and logs the cause. Compare errors
  with `errors.Is` and `errors.As`, never with `==`.
- Logs go through `log/slog` via `internal/pkg/logger`; inside a request take the logger from the
  context (`logger.FromContext`), so records carry `request_id` and `user_id`. Never log passwords,
  tokens, emails or the webhook URL. Driver messages go there too: `internal/app` opens every MySQL
  pool through `mysqlConnector`, which sets `logger.MySQLLogger` on the connector (open new pools the
  same way), and `cmd/api` installs `logger.RedisLogger` with `redis.SetLogger`.
- Context is the first argument of everything that does I/O; never `context.Background()` on a
  request path.
- SQL names its columns: no `SELECT *`. Repositories map `sql.ErrNoRows` to `NOT_FOUND` and duplicate
  keys to `CONFLICT`.
- Partial updates use `opt.Field[T]`, which tells an absent field from `null` and from a value.
  Handler DTOs are mapped to port inputs; domain types never see JSON.
- Schema changes go into a new numbered migration with up and down files; never edit the up file of
  an applied one. A down file restores the schema of the version before it exactly and succeeds on
  any data the API accepts; the integration suite checks every step.
- Mocks are generated with `go generate` (mockgen pinned in `test/mocks/doc.go`); do not edit them by
  hand.
- Tests are table-driven, call `t.Parallel()`, use testify `require` for errors and assert the
  arguments passed to collaborators, not just the absence of an error. Anything touching MySQL or
  Redis also needs coverage in `test/integration`.
- Use `any`, not `interface{}`. Every exported identifier has a doc comment ending with a period;
  comments explain why, not what.
- A route added to the router must be added to `api/openapi.yaml`; a test compares both.
- Never commit secrets or `.env`.
